# Extraction Rules v1

이 문서는 PoC 추출 결과에서 `Decision`, `Task`, `Issue`, `Event`를 구분하는 기준입니다.

## Decision

다음 조건을 모두 만족할 때 Decision으로 분류합니다.

- 선택, 승인, 합의, 채택, 중단처럼 방향이 확정되었다.
- 누가 무엇을 선택했는지 원문 근거가 있다.
- 단순 제안, 질문, 검토 예정 또는 개인 의견이 아니다.

기존 결정을 명시적으로 폐기하거나 다른 선택으로 교체한 경우에만
`supersedes_decision_id`를 설정합니다.

## Task

실행할 행동이 명확하고 다음 중 하나 이상이 존재할 때 Task로 분류합니다.

- 담당자
- 기한
- 완료 조건
- 명시적인 요청 또는 약속

결정에 실행 항목이 포함되어 있으면 Decision과 Task를 각각 생성하고
`RESULTED_IN` 관계로 연결합니다.

## Issue

해결이 필요하지만 아직 해결책이 확정되지 않은 문제, 위험, 장애물입니다. 해결책이
확정되면 Issue를 유지하고 해당 Decision과 `RESULTED_IN` 또는 `RELATED_TO`로 연결합니다.

## Event

특정 시점에 실제로 발생해 프로젝트 상태를 바꾼 사실입니다. 예정일만 있는 항목은
Task의 due_at으로 표현하고, 타임라인 표시를 위해 별도 Event가 필요할 때만 생성합니다.

## 근거 규칙

- 모든 추출 항목은 하나 이상의 `source_ref`를 가져야 합니다.
- 원문에 없는 담당자, 날짜, 인과관계를 추론해 채우지 않습니다.
- 근거가 부족하면 해당 필드를 `null`로 두거나 결과에서 제외합니다.
- 요약은 원문의 의미를 보존하고 새로운 사실을 추가하지 않습니다.
