# 무료 배포에서 녹음·문서 처리

상태: 검토안. 현재 운영 API에는 Celery broker와 별도 worker가 연결되어 있지 않습니다. 아래 방식은 아직 구현·활성화하지 않았습니다. 리전과 무료 플랜은 유지합니다.

## 권장 구성

기존 Render API 안에서 동시에 한 건만 처리하고, 작업 상태와 재시도 시각은 기존 Supabase PostgreSQL에 저장합니다. 원본 녹음은 기존 Storage에 보관합니다. 브라우저는 현재 작업 조회 API로 진행 상황을 확인합니다. 새 Redis나 유료 worker 서비스를 만들지 않습니다.

이 방식에는 실행기 구현이 필요합니다. 현재 Celery enqueue를 그대로 두고 환경변수만 바꾸는 것으로는 동작하지 않습니다.

- 업로드·대본 확정과 작업 등록을 같은 DB 트랜잭션으로 처리합니다.
- 작업에는 source ID, 처리 단계, 시도 횟수, 다음 실행 시각, lease 만료 시각을 저장합니다. source와 처리 단계별 중복 등록을 막습니다.
- API 시작 및 정상 사용자 요청 시 대기 작업 실행을 깨웁니다. 작업 선점에는 DB lock/lease를 사용합니다.
- 기존 단계별 체크포인트를 재사용하고, lease가 만료된 작업을 재시도합니다. 재시작 후 완료된 추출·그래프 쓰기를 중복 적용하지 않아야 합니다.
- 서버 STT 완료 후에는 `awaiting_review`에서 멈춥니다. 사용자가 화자·발언을 수정하고 확정해야 분석합니다.
- 동시 실행은 1건으로 제한하고, 파일 크기·시간 제한과 처리 오류를 화면에 표시합니다. 외부 API 호출은 웹 요청 처리 루프를 막지 않아야 합니다.

## 무료 플랜의 한계

Render 무료 Web Service는 15분 동안 외부 요청이 없으면 잠들고, 다시 접속하면 기동 시간이 발생합니다. 임의 재시작도 가능합니다. 따라서 사용자가 떠나도 항상 즉시 완료되는 상시 worker와 같은 보장은 할 수 없습니다. 대기 작업은 DB에 남겨 다음 접속·기동 때 재개해야 합니다. 인위적인 keep-alive로 이 제약을 우회하는 구성은 포함하지 않습니다.

Render의 별도 Background Worker는 무료 대상이 아닙니다. 무료 Key Value는 재시작 시 메모리 데이터가 사라질 수 있으므로 유일한 작업 보관소로 쓰지 않습니다. STT·LLM 공급자의 사용료는 서버 무료 플랜과 별개입니다.

## 구현 전 검증 기준

1. 처리 중 API를 종료하고 다시 시작해도 같은 작업이 복구되어야 합니다.
2. 동시 업로드·중복 요청·lease 만료 시에도 같은 자료를 중복 분석하지 않아야 합니다.
3. 원문·화자 편집은 확정 전까지 분석에 포함되지 않아야 합니다.
4. STT 오류·공급자 제한·DB 일시 장애를 구분해 제한된 재시도를 해야 합니다.
5. 실제 Render 메모리 사용량과 API 응답 지연을 짧은 오디오로 측정해야 합니다.
