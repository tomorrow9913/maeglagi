# 맥락이 브랜드·디자인 기준

제품 정의와 브랜드 자산, 디자인 토큰의 단일 기준 문서입니다. 화면 카피나 색을 새로 정하기 전에
여기부터 확인하고, 여기 없는 값은 만들지 않습니다.

대응 작업: TSK-20(제품 정의·슬로건), TSK-12(로고·워드마크), TSK-28(캐릭터), TSK-10(디자인 토큰).
말투는 TSK-6에서 따로 다룹니다.

## 1. 제품 정의 (TSK-20)

- **서비스명**: `맥락이`
  - 서비스명과 AI 캐릭터명을 분리하지 않습니다. 화면 안에서 말을 거는 주체도 `맥락이`입니다.
  - 영문 병기(`Maeglagi`)는 패키지명·도메인 등 식별자에만 쓰고, 화면 카피에는 노출하지 않습니다.
- **한 문장 정의**: 회의와 문서처럼 흩어진 업무 정보를 AI가 연결해 사람·프로젝트·결정·업무·이벤트의
  관계와 현재 맥락을 자동으로 만드는 Organizational Context Platform
- **슬로건**: 흩어진 업무의 맥락을 잇다
- **보조 설명 한 줄**: 회의와 문서에서 결정, 이슈, 할 일을 연결하고 왜 그런 결정이 나왔는지 근거와 함께 답합니다.

쓰는 곳이 정해져 있습니다. 세 문장을 섞어 쓰지 않습니다.

| 문장 | 쓰는 곳 |
| --- | --- |
| 슬로건 | 랜딩 h1, 발표 자료 표지, 헤더 태그라인 |
| 한 문장 정의 | README 첫 문단, `metadata.description`, 발표 첫 장 설명 |
| 보조 설명 | 랜딩 서브카피, 스토어·문서 요약 |

말투와 화자 규칙은 [voice.md](voice.md)에 따로 있습니다. 근거가 없으면 지어내지 않고 없다고
답하는 것이 카피 규칙이자 제품 규칙입니다.

## 2. 로고·워드마크 (TSK-12)

구현: `frontend/src/components/brand/logo.tsx`

- **심볼** `MaeglagiMark` — 아래로 흩어진 두 가닥이 위에서 하나의 고리로 감기는 실타래입니다.
  제품이 하는 일을 그대로 형태로 옮긴 것이므로, 가닥 수나 교차 위치를 임의로 바꾸지 않습니다.
- **워드마크** `MaeglagiWordmark` — 심볼 + `맥락이` 락업. 부제나 영문을 붙이지 않습니다.
  심볼 크기는 글자 크기의 1.15배로 고정돼 있어 `text-sm`, `text-lg`만 바꾸면 비율이 유지됩니다.
- **색** — 심볼은 `currentColor`를 따릅니다. 기본은 `text-primary`, 브랜드 색 위에 올릴 때만 `text-card`.
- **최소 크기** — 심볼 16px, 워드마크 `text-sm`. 그보다 작게 쓸 일이 생기면 심볼만 씁니다.
- **금지** — 회전, 그림자, 그라디언트, 단색 외 채우기, 워드마크 안 글자 자간 임의 변경.

앱 아이콘·파비콘은 Next.js 메타데이터 파일 규칙으로 자동 주입됩니다.

| 파일 | 산출물 |
| --- | --- |
| `frontend/src/app/icon.svg` | 파비콘. 브랜드 색 배경 + 흰 심볼, 모서리 반경 7.5/32 |
| `frontend/src/app/apple-icon.tsx` | iOS 홈 화면 아이콘 180×180 PNG. 정적 파일 규칙이 SVG를 받지 않아 빌드 시점에 굽습니다 |

## 3. 캐릭터 (TSK-28)

구현: `frontend/src/components/brand/maeglagi-character.tsx`

실타래 몸통에서 실 한 가닥이 풀려 나오는 모습입니다. 심볼과 같은 은유를 쓰되 역할을 나눕니다.
심볼은 제품을 가리키는 마크, 캐릭터는 사용자에게 말을 거는 화자입니다.

포즈는 두 가지뿐입니다. 표정을 새로 만들지 않습니다.

| 포즈 | 모습 | 쓰는 곳 |
| --- | --- | --- |
| `default` | 눈을 뜨고 정면 | 답변 화자 아바타 (`MaeglagiAvatar`) |
| `resting` | 눈을 감고 실이 길게 풀림 | 빈 상태(`EmptyState` 기본 아이콘), 답변 대기 중 |

- 크기: 아바타 `size-8`, 빈 상태 `size-9`, 화면 중앙 안내 `size-12`.
- 색: `text-primary`. 캐릭터 안에서 색을 두 개 이상 쓰지 않습니다. 몸통 채움은 같은 색 16%입니다.
- 애니메이션은 캐릭터 자체에 넣지 않고, 필요하면 쓰는 쪽에서 감쌉니다.

## 4. 디자인 토큰 (TSK-10)

구현: `frontend/src/app/globals.css`의 `:root`. 여기가 값의 원본이고 이 문서는 근거를 적어 둔 곳입니다.

라이트 모드 한 세트만 운영합니다. 다크 모드는 PoC 범위 밖입니다.

### 4-1. 색

sage green(브랜드) + warm buff(배경) 조합입니다. 회의록·문서를 오래 읽는 화면이라 순백 대신
따뜻한 종이 톤을 바탕으로 깔고, 강조는 채도가 낮은 초록 하나로만 줍니다.

색을 고를 때 지키는 규칙은 두 가지입니다.

1. **중립은 배경의 warm buff 계열(H 88~91)로 통일합니다.** 캐릭터가 이 바탕 위에 앉기 때문에,
   면과 선이 다른 계열이면 캐릭터의 sage만 떠 보입니다.
2. **유채색 축은 캐릭터가 쓰는 sage 하나뿐입니다.** 나머지 색은 의미를 구분하려고 쓰는 것이므로
   배경 대비 4.5:1 이상을 지킵니다. 대비가 모자라면 채도가 아니라 명도를 내립니다.

| 토큰 | oklch | hex | 용도 |
| --- | --- | --- | --- |
| `--background` | `oklch(0.9643 0.007 88.64)` | `#f5f3ee` | 페이지 바탕 |
| `--foreground` | `oklch(0.2737 0.0223 171.93)` | `#1c2b26` | 본문 |
| `--card` / `--popover` | `oklch(0.9945 0.0057 88)` | `#fffdf9` | 카드·팝오버 면 |
| `--primary` | `oklch(0.5071 0.0627 168.97)` | `#3e715f` | 브랜드, 주요 버튼, 링크 |
| `--secondary` / `--muted` | `oklch(0.946 0.0124 91.52)` | `#f0ede4` | 보조 면 |
| `--muted-foreground` | `oklch(0.515 0.02 169)` | `#5d6b65` | 보조 텍스트. 배경 대비 5.04 |
| `--accent` | `oklch(0.919 0.0154 90.24)` | `#e8e4d9` | 호버·선택 면 |
| `--accent-foreground` | `oklch(0.4315 0.0547 169.06)` | `#2f5a4b` | 강조 면 위 텍스트 |
| `--border` / `--input` | `oklch(0.888 0.014 89)` | `#dedad0` | 선 |
| `--ring` | `--primary`와 동일 | `#3e715f` | 포커스 링 |
| `--destructive` | `oklch(0.5175 0.1659 27.99)` | `#b4342c` | 오류 |
| `--success` | `oklch(0.5214 0.0981 156.97)` | `#2f7a52` | 완료 |
| `--warning` | `oklch(0.545 0.12 70)` | `#9c6100` | 주의·진행 지연. 배경 대비 4.59 |
| `--info` | `oklch(0.5285 0.1031 251.92)` | `#3b6ea5` | 안내 |
| `--radius` | — | `0.75rem` | 반경 기준값. sm·md·lg는 여기서 계산됩니다 |

색 표기는 HSL이 아니라 **oklch**를 씁니다. Tailwind v4와 shadcn 기본 테마가 oklch를 쓰고,
밝기를 고정한 채 색상만 바꿀 때 HSL보다 결과가 예측 가능해서입니다. 디자인 도구에서 옮겨올 때만
위 표의 hex를 쓰고, 코드에는 oklch 값을 넣습니다.

### 4-2. Knowledge Graph 노드 색

`--chart-1..5`를 Ontology entity 종류에 1:1로 고정합니다. 순서를 바꾸면 그래프 범례가 어긋납니다.
다섯 색은 배경 대비 4.67~4.78로 맞춰 한 가족처럼 보이게 했습니다. 특정 노드만 더 짙거나 흐리게
보이면 데이터가 아니라 색이 강조를 만들어 버리기 때문입니다.

| 토큰 | entity | hex |
| --- | --- | --- |
| `--chart-1` | Person | `#30785d` |
| `--chart-2` | Project | `#3a6ea7` |
| `--chart-3` | Decision | `#a6552d` |
| `--chart-4` | Task | `#795ea7` |
| `--chart-5` | Event | `#816b21` |

`<canvas>`에 직접 그리는 그래프 라이브러리는 `oklch()` 문자열을 해석하지 못해 색을 잃습니다.
그래서 같은 값을 `--chart-N-hex`로 한 번 더 둡니다. 값을 바꿀 때 두 줄을 함께 고쳐야 합니다.

### 4-3. 타이포

- 폰트: Geist(라틴) + 시스템 한글 폰트(`--font-sans`). 한글 자소는 OS 기본 폰트가 받습니다.
- 크기는 **Tailwind 스케일만** 씁니다. `text-[13px]` 같은 임의 px 값은 쓰지 않습니다.

| 역할 | 클래스 |
| --- | --- |
| 랜딩 h1 | `text-5xl sm:text-7xl font-semibold tracking-tighter` |
| 페이지 제목 | `text-2xl font-semibold tracking-tight` |
| 섹션 제목 | `text-lg font-semibold` |
| 본문 | `text-sm` (긴 설명은 `text-base leading-relaxed`) |
| 보조·캡션 | `text-xs text-muted-foreground` |
| 오버라인 | `text-xs font-extrabold tracking-[0.16em] text-primary` |

### 4-4. 색을 직접 쓰는 예외

토큰 대신 hex를 직접 쓰는 곳은 두 군데뿐이고, 둘 다 이유가 있습니다. 새로 늘리지 않습니다.

- `src/app/global-error.tsx` — 루트 레이아웃이 통째로 교체되는 화면이라 `globals.css`가 로드되지 않습니다.
- `src/features/knowledge-graph/lib/graph-style.ts` — canvas 렌더러가 oklch를 못 읽어 `--*-hex` 토큰을 읽습니다.
